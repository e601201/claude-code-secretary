# 立ち絵の素材はユーザーが 1 枚のシートで持ち込む

秘書の立ち絵はイラストであり、どの絵を使うかは使う人ごとに違う。素材を同梱して配る案と、
仕様だけ決めて使う人に持ち込ませる案を比べ、**素材はユーザーが 1 枚のシート
(`<設定フォルダ>/character.png`、6 行 × 4 列)で持ち込み、リポジトリは仕様
(`docs/character-sheet.md`)とプレースホルダーだけを持つ**と決めた。

## Considered Options

- **素材を同梱する**: 絵の権利も好みも人によって違ううえ、絵を差し替えるたびにアプリの
  再ビルドが要る。開発リポジトリが数十 MB の画像を抱えることにもなる
- **状態ごとに 6 枚に分ける**: 状態単位の遅延読み込み(常用は idle / thinking / working だけ)と、
  部分提供(waiting だけ後から足す、error だけ描き直す)ができる。代わりに、使う人が
  管理するファイルが 6 つに増える
- **1 枚のグリッド(採用)**: 使う人が触るファイルが 1 つで済み、設定フォルダで
  `config.toml` / `persona.toml` と並べて「3 つ目のファイル」として説明できる。
  素材を人手で作る前提では、説明のしやすさが遅延読み込みより効く

## Consequences

- **部分提供ができない。** 描けていない行(たとえば waiting)は透明のまま置くことになり、
  その状態のあいだ立ち絵は消える。アプリは他の行で代用しない
- **遅延読み込みができない。** 全状態が常にメモリに乗る。推奨寸法(1920×3840)で約 29.5MB。
  1 コマの寸法がそのまま常駐量になるので、仕様書は寸法を「推奨」として明示する
- **手続き的な CSS アニメーションは撤去する**(breathe / tilt / work / jump / shake)。
  動きはシートの中にしか無い。素材を置いていないユーザーの画面では、
  プレースホルダーの 4 コマだけが動く
- **契約を後から変えると、シートを作った全員が作り直しになる。** 行の順序は
  `docs/state-machine.md` の状態表と `ALL_STATES` に合わせてあるので、状態を増やすときは
  この 3 か所が同時に動く
- **読めないシートを黙って落とさない。** 寸法が合わなければプレースホルダーに落ちるが、
  落ちた事実と理由は設定ウィンドウに出す。黙って切ることが #1 の原因だった(ADR-0001)
