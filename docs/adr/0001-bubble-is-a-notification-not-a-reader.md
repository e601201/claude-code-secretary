# 吹き出しは通知であって読み物ではない

秘書の吹き出しは長い発言を出しきれず（`-webkit-line-clamp: 4` と `max_message_chars` の二重の切断）、全文を読む手段が無かった。吹き出し自体をスクロール可能にする・長文時にウィンドウを伸ばすといった「吹き出しを読み物にする」案を検討したうえで、**吹き出しは通知に徹し、全文は独立ウィンドウ（全文ビュー）で読ませる**と決めた。

## Considered Options

- **吹き出しをスクロール可能にする**: キャラクターウィンドウは 280×444 固定で、吹き出しに使える高さは約 128px しかない。長文とこの寸法が根本的に釣り合わない。加えて吹き出しは `pointer-events: none` で、クリックの当たり判定は Rust 側の `cursor_watch` がキャラクター矩形で決めている。吹き出しを触れるようにするには、ウィンドウ全体を当たり判定にする（背後 280×444 のクリックを全部奪う）か、webview から Rust へ吹き出しの実寸を送り続けるかのどちらかになる
- **長文のときだけウィンドウを伸ばす**: `BASE_HEIGHT`、webview 側の zoom 計算、保存済みウィンドウ位置、`cursor_over_figure` の座標計算すべてに波及する
- **別ウィンドウ（採用）**: `settings.html` に前例があり、透過ウィンドウのヒットテスト・ドラッグ判定・座標計算という最も壊れやすい部分に一切触れない

## Consequences

- 全文ビューを開く導線は吹き出しのクリックではなく、キャラクターの右クリックメニューとトレイメニューに置く。この 2 つを選んだのは、上の「壊れやすい部分に触れない」という利点をトリガーで台無しにしないため
- 吹き出しの表示時間（最大 12 秒）は据え置く。読み切らせる必要が無くなったので、伸ばす理由も無い
- 「読ませないが、読む手段は常にある」が成立条件。全文ビューへ到達できない状態を作ってはいけない（トレイにも項目を置くのはこのため。クリック透過が常時オンだとキャラクターを右クリックできない）
